# Receiver-epoch finite audit

This supplemental audit is separate from the frozen nine-family campaign. Its scope is the pointwise domination premise of the receiver-epoch postponement lemma, not new workload breadth or a mechanized general proof. The selection was fixed before running this audit.

Use one worker and the standard library. Generate 96 cases with seed 910743: n is uniform in 2..4; H in 3..7; each has 1..5 predetermined messages with positive transmission time and an interval of one or two integer slots. Choose up to two mandatory and up to two eligible optional reset events without replacement. Enumerate every optional subset and every arrival assignment. For every message and every strictly later arrival in its interval, compare complete scalar state histories when the receiver has no reset between the old and new arrivals (excluding the old slot, including the new slot). All nodes at every slot must have no larger watermark after postponement. Also check that canonicalizing all arrivals to epoch ends preserves or lowers the complete history and preserves a stale query.

The scalar audit simulator is a separate full-slot implementation. It does not call the closure producer or the event-sorted replay. Output retains each exact input, per-case enumeration counts, and the aggregate resource observation. A mismatch aborts and writes its exact instance, optional pattern, arrival assignments, and state histories. Retain a negative control in which postponement crosses a receiver reset and increases the query answer; a control that fails to distinguish that case is not a pass.

Run with `python epoch_audit.py --out results/epoch-audit`. Compare scientific rows, excluding resource measurements, on clean reproduction. Budget: at most 60 CPU seconds and 256 MiB process RSS for this audit, one worker, one bounded run. The 8 CPU-hour project campaign ceiling remains binding. This audit does not alter the original 60,026-execution campaign denominator.
