# Source-grounded boundary of the claims

This is a technical source audit, not a claim of exhaustive literature coverage. URLs and precise read representations are in `external_resources.csv`. No publication is used as experimental input. Full-paper reading does not imply independent source review by a second person.

| Source and passage | Verified content and consequence for this project |
|---|---|
| Coral, NSDI 2004, DSHT interface and design/evaluation sections | Soft-state `put(k,v,ttl,[levels])` and subset retrieval distribute mappings using sloppy placement. Its architectural/load evidence does not establish an authoritative as-of snapshot. The present source-watermark and reset semantics require new arguments, not a renaming of Coral. |
| TTL consistency, TPDS 2008, §3.2 | An expired copy is not served under the same semantics as a still-valid replica. Served-copy staleness already has a deterministic TTL boundary. Our batch is non-abstaining and exogenous, with volatile erasure. |
| GeWave, §4.1 | TTR, geographical polling and owner fallback support file consistency. We do not claim it provides no freshness guarantee; it does not state our universal prescribed-schedule/reset certificate problem. |
| IRM, §§3.2 and 5 | Adaptive TTR and owner fallback are part of the design; the conclusion explicitly declines a guarantee that every requester receives the up-to-date version. The author-hosted published text and Figures 1, 2 and 8 were inspected; no numerical performance is transferred to this project. |
| EAD, TPDS 2010 accepted journal text, §§2.2.5–2.2.6, 3.5–3.7 and 5 | Query-rate adaptation determines replica creation/deletion. The reported churn simulation uses voluntary departures with replica transfer; unexpected failures are discussed separately. This is a different model from fixed sends and repeated instantaneous erasure. Its efficiency evidence does not establish our universal as-of-age certificate. The full journal manuscript, not the earlier P2P paper, was read. |
| TACT, §3.2 and §3.4 | Staleness is a defined continuous-consistency dimension; time vectors and compulsory propagation enforce the declared limit. The discussion distinguishes pull enforcement from unbounded push delays. Bounded staleness, completeness metadata and formal recency are not claimed as new here. |
| ASC/PAB, Theorem 3.2 and evaluation | A deterministic version-distance bound accompanies probabilistic atomicity. This is not merely a probabilistic predecessor. It uses quorum/failure assumptions, not as-of age under instantaneous repeat erasure. |
| PBS, §1.2 and §6 | It acknowledges deterministic predecessors and develops version/time probabilities for partial quorums. The latency analysis does not model failures. We do not compare a worst-case theorem to its probability values as an empirical speedup. |
| Hampa, recency and coordination arguments | Recency is value drift rather than wall-clock age; solver-aided coordination and failure assumptions are explicit. Formal automatic recency reasoning already exists. |
| Weak-consistency specification framework, model and case studies | Visibility, arbitration and additional relations support generic replicated-data semantics. Our thresholded maximum snapshot is much less general. Alloy support is future work in the read paper, not an existing measured artifact. |
| Diskless recovery, Definition 7 and shared-object constructions | Crash-consistent quorums address safety after volatile loss. We do not provide a quorum recovery implementation or claim atomic register semantics. |
| Self-stabilizing snapshot objects, TCS 2026, §§1.1–1.4 only | The task is linearizable SWMR snapshots; the model lacks a communication-delay bound and allows recovery after the last arbitrary transient fault. This is distinct from continuous bounded erasures under a fixed refresh schedule. Only this model contrast is used; later proof sections are not claimed as read or as an extra calibration paper. |
| Continuous-churn register, 2017 preprint model and Theorems 9, 14, 21 | Under bounded joining/leaving/crashed fractions, the protocol supports ongoing membership change and atomic operations. Those fractions, unknown delay bound and active-node assumptions differ from our fixed identities and rolling event count. The 2019 TPDS journal metadata is verified, but full equivalence to the read preprint is not established. The manuscript therefore cites the actual preprint read. |
| Temporal Connectivity, offline/online definitions | Delay choices affect journeys with waiting; online path selection has different quantifiers from offline robustness. Volatile resets remove persistent waiting, except within a receiver epoch. |
| Robust Temporal Cut, problem definition and Theorem 8 | A chosen cut must withstand all allowed timing perturbations. It already proves hard temporal cut cases. Our unsafe witness instead chooses resets and arrivals together. No generic first-hardness claim is made. |
| Reachability under Perturbation, opening definitions only | It selects timestamp perturbations to improve reachability. Only this checked model distinction is used; the unread remainder is not counted as full calibration. |
| Tree placement, Theorems 2--5 | Uncapacitated tree placement admits dynamic programming; general capacity changes complexity, and the normal-assignment result is scoped. We do not generalize our fixed-arrival cut beyond its unit per-event objective. |
| Minimal-cost dynamic web replication, Theorems 1--4 | Dependency-aware maintenance choices have a cost-preserving cut representation. Min-cut as a replication primitive is established prior work. |
| Dynamo, §§4.4--4.7 | Vector contexts, reconciliation and hinted handoff support availability-oriented replication and recovery. Such contexts alone are not real-time authoritative completeness. |
| Spanner, §§3, 4.1.2--4.1.3 and Appendix A | Bounded clock uncertainty, commit wait and safe time support operational read semantics. Our global discrete time is an assumption, not an implementation of that infrastructure. |

The project-specific contribution hypothesis is the exact delay/reset schedule characterization, its coherent certificate/counterexample pair, the fixed-arrival versus interval-arrival complexity separation on the same semantics, and the direct-replica rolling-budget phase formula. Horn propagation, balanced range decomposition, Fenwick counts, minimum cut and sorted common-deadline packing are established ingredients. Their use alone is not evidence of novelty. Significance and the completeness of the closest-work comparison remain matters for substantive external expert review; no acceptance claim follows from the finite checks.

## Fixed-route robustness comparison

Füchsle, Molter, Niedermeier and Renken, *Delay-Robust Routes in Temporal Graphs*, STACS 2022, DOI 10.4230/LIPIcs.STACS.2022.30, fixes a vertex sequence before universally quantifying over up to a budget of delayed time arcs. Temporal walks may choose different contacts but must follow that same sequence (section 2, p. 30:4). Theorem 5 gives polynomial recognition of a supplied route, while Theorem 7 states NP-completeness of finding a suitable route. The present freshness guarantee preselects neither a route nor a surviving replica; reset erasures also invalidate unrestricted waiting. This is a model and quantifier distinction, not an assertion that our result supersedes route synthesis. The published introduction, definitions, recognition outline and hardness statement were inspected. Proofs deferred to the full version were not read; this is not another full-paper calibration entry.
